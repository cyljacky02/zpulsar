# Win32 interop strategy for zPulsar on Zig 0.16

Research for issue [#7](https://github.com/cyljacky02/zpulsar/issues/7). Date: 2026-08-14.
Environment: Zig 0.16.0 (winget build, `zig env` verified), Windows 11 Pro 26200, Windows SDK 10.0.26100.0 headers used as struct ground truth.

## Verdict

**Use zigwin32 (marlersoft/zigwin32, `main` branch pinned to an exact commit via `zig fetch`) as the primary binding layer, with a thin repo-owned `src/win32.zig` re-export facade plus comptime layout assertions for the structs we feed across the ABI. Hand-roll nothing up front; fall back to a hand-rolled `extern` only where zigwin32 is wrong or missing (one known case: the ETW buffer callback type, see F6). Do not use `translate-c` as the primary mechanism.**

All three approaches were compile-tested on Zig 0.16.0 on this machine; the zigwin32 and hand-rolled test programs **compiled and executed successfully**, each retrieving a live TCP owner-module table (~300 rows) and starting + stopping a real ETW session via `StartTraceW`/`ControlTraceW` (elevated shell, rc=0). The translate-c output also compiled and called `GetExtendedTcpTable` successfully. Compile/run logs are reproduced in the Appendix.

Why zigwin32 wins:

1. **It actually works on 0.16 today** — verified by compile+run, not by README (the READMEs are stale; see F1).
2. **It covers the entire zPulsar surface** in one dependency: `dll/advapi32.zig` 607 extern fns (ETW control + SCM), `dll/tdh.zig` 27, `dll/fwpuclnt.zig` 192 (WFP), `dll/iphlpapi.zig` 196, `dll/ws2_32.zig` 160, `dll/shell32.zig` 243, plus generated COM vtables for all of D3D11/DXGI (F4). Hand-rolling that surface is ~500+ declarations dominated by COM vtables where a single slot miscount is a silent wrong-method call (F8).
3. **Spot-checks of the notorious structs matched the SDK 26100 headers field-for-field**: `EVENT_TRACE_LOGFILEW`, `FWPM_NET_EVENT_HEADER2`, `MIB_TCPROW_OWNER_MODULE`/`MIB_TCPTABLE_OWNER_MODULE` (variable-length `[1]row` pattern preserved) (F5).

Guardrails to adopt with it:

- **Pin the exact commit.** zigwin32 has no tags or releases; `zig fetch --save=zigwin32 "git+https://github.com/marlersoft/zigwin32#main"` records both the commit and a content hash in `build.zig.zon` (this research pinned `9f15c276`, package version `42.0.39-preview`), so builds are reproducible and upstream churn (a large July 2026 reorganization moved every function into per-DLL namespaces) cannot bite silently (F2, F3).
- **Comptime-assert layouts of ABI-crossing structs** against SDK-derived `@sizeOf`/`@offsetOf` values (demonstrated in the hand-rolled example below). The generator has a real history of layout/type bugs: marlersoft/zigwin32#37 (wrong alignment in `IMAGE_OPTIONAL_HEADER64`), #46 (wrong struct field types), #6 (by-value struct returns broken for d3d12), #48 (HidP segfault, fixed) (F6).
- **Define our ETW buffer callback with the true SDK signature** — zigwin32 stubs `PEVENT_TRACE_BUFFER_CALLBACKW` as `*const fn() callconv(.winapi) void` due to a generator dependency loop; the real type is `ULONG (WINAPI *)(PEVENT_TRACE_LOGFILEW)` (evntrace.h:1521). Write the callback with the real signature and `@ptrCast` it into the struct field; the caller (ETW) uses the real ABI, so this is a type-level wart, not an ABI break (F6).
- **Wrap the import behind `src/win32.zig`** so the rest of the codebase never spells `@import("win32").everything` — one file to touch if upstream reorganizes again or a declaration needs a hand-rolled override.

## Findings

### F1. zigwin32 maintenance state: active; docs stale; 0.16-compatible in practice

- Repo pushed **2026-07-23** (`gh api repos/marlersoft/zigwin32` → `pushed_at: 2026-07-23T01:40:51Z`); ten substantive commits in July 2026 alone ("organize functions by dll", "remove unicode aliases and UNICODE option", "use packed struct for hresult", "redirect NTSTATUS to std", "virtual dlls").
- The fetched package's `build.zig.zon` declares `.minimum_zig_version = "0.14.0"` and `.version = "42.0.39-preview"`. The bindings use `callconv(.winapi)` throughout (introduced for 0.14; migration tracked in marlersoft/zigwin32#38), which is exactly the portable convention Zig 0.16's `std/builtin.zig:132` defines per-arch (`x86_64_win` on x64, `x86_stdcall` on x86).
- Documentation is unreliable: the zigwin32gen README still says "currently tested on 0.12.0-dev", and DeepWiki's index claims 0.11–0.13 support. **The compile+run test on 0.16.0 is the controlling evidence** (Appendix A/B).
- Distribution model: no tags, no GitHub releases; versioned throwaway branches (`25.0.28-preview`, …) plus `main`. Consumption is `zig fetch` against a commit. Generated by [marlersoft/zigwin32gen](https://github.com/marlersoft/zigwin32gen) from Microsoft's win32metadata (via marlersoft/win32json) — the same metadata source that feeds Microsoft's own windows-rs.

### F2. The July 2026 reorganization (API churn risk)

Commits of 2026-07-18..23 moved every extern function out of topic modules (`win32.network_management.ip_helper`) into per-DLL modules (`dll/iphlpapi.zig`, re-exported as `win32.iphlpapi`), removed the `UNICODE` option and A/W-less aliases, and rebuilt `win32.everything` as the flat namespace re-exporting both. My first test build failed precisely because of this move (`ip_helper` no longer has `GetExtendedTcpTable`; `win32.everything` and `win32.iphlpapi` do). Types stayed in topic modules. Conclusion: the project is alive but reserves the right to reshuffle; pin the commit and route imports through one facade file.

### F3. What Zig-on-Windows projects do (community norms)

- `std.os.windows` in 0.16 ships bindings only for **kernel32, ntdll, ws2_32, crypt32** (plus ntstatus/win32error enums) — verified by listing `lib/std/os/windows/` in the installed 0.16.0 std. Nothing for ETW, TDH, WFP, IP Helper, SCM, shell32, D3D11/DXGI. The 0.16 release notes double down on ntdll-level implementation for std itself ("all standard library functionality is now implemented based on calls to the lowest level stable syscall API") — std is not trying to become a Win32 binding set.
- GitHub code search: **136 `build.zig.zon` files reference zigwin32** (`gh api search/code`), including active, well-known projects: david-vanderson/dvui (GUI toolkit), Cloudef/zig-aio, kristoff-it/awebo, fabioarnold/MiniPixel. That is the de-facto community norm for broad Win32 surfaces; projects touching only a handful of calls hand-roll externs instead.
- Zig 0.16 std API churn is real and ongoing (this research tripped over `std.fs.File` → `std.Io.File` and `std.os.windows.BOOL` becoming a typed enum rather than `c_int`). A generated binding pinned per-commit insulates the Win32 layer from that churn better than 500 hand-written declarations.

### F5. Struct ground truth: zigwin32 vs Windows SDK 10.0.26100.0

Spot-checked field-for-field against the installed SDK headers:

- `EVENT_TRACE_LOGFILEW` (etw.zig:1207 vs evntrace.h:1600ff): matches, including both anonymous unions (`LogFileMode`/`ProcessTraceMode` and `EventCallback`/`EventRecordCallback`).
- `FWPM_NET_EVENT_HEADER2` (windows_filtering_platform.zig:1376 vs fwpmtypes.h:722): matches, including both V4/V6 address unions — the WFP structs the ticket flagged as notorious.
- `MIB_TCPROW_OWNER_MODULE` / `MIB_TCPTABLE_OWNER_MODULE` (vs tcpmib.h:143): matches; variable-length tables use the C `[1]row` trailing-array idiom, consumed by pointer-casting a runtime-sized buffer (as in both working examples below).
- `StartTraceW`'s first parameter: SDK 26100 renamed it to `CONTROLTRACE_ID*` where `typedef ULONG64 CONTROLTRACE_ID` (evntrace.h:307/1731); zigwin32's `CONTROLTRACE_HANDLE = u64` (etw.zig:660) is ABI-identical to both that and the classic `PTRACEHANDLE`.

### F6. Known zigwin32 correctness hazards (with mitigations)

- `PEVENT_TRACE_BUFFER_CALLBACKW` is **stubbed** as `*const fn() callconv(.winapi) void` with a generator TODO ("this function pointer causes dependency loop problems, so it's stubbed out", etw.zig:1604–1608). True SDK type: `typedef ULONG (WINAPI * PEVENT_TRACE_BUFFER_CALLBACKW)(PEVENT_TRACE_LOGFILEW)` (evntrace.h:1521). Mitigation: declare the callback with the true signature locally, `@ptrCast` when assigning to `EVENT_TRACE_LOGFILEW.BufferCallback`. Layout of the struct itself is correct (it is just a pointer field).
- Open issues showing the bug classes metadata generation produces: #37 wrong alignment (`IMAGE_OPTIONAL_HEADER64`), #46 wrong field types (`LOGFONTA`), #6 d3d12 by-value struct returns, #47 non-optional callback param that should be optional; #48 (HidP segfault) was fixed. None touch zPulsar's verified structs, but they justify comptime `@sizeOf`/`@offsetOf` asserts on every struct we pass across the ABI.

### F7. translate-c on 0.16: works, but wrong tool for this

- The standalone CLI still exists in 0.16 (`zig translate-c api.c -target x86_64-windows-gnu -lc` succeeded, producing 105,009 lines from windows.h+evntrace.h+evntcons.h+tdh.h+iphlpapi.h), and the consumer program compiled and ran (Appendix C). However the 0.16 release notes deprecate `@cImport` in favor of `b.addTranslateC()` — the workflow is moving into the build system.
- Output problems for this use case: (a) functions get `callconv(.c)` and no DLL association (`pub extern fn StartTraceW(...)`), correct on x64 only — an x86 build would silently use the wrong convention, unlike `.winapi`; (b) **2,261 `@compileError` placeholders** for untranslatable macros — any needed constant that lands on one must be re-declared by hand; (c) the headers actually translated are Zig's bundled **mingw-w64** headers, not the Microsoft SDK — e.g. it emitted the classic `PTRACEHANDLE` signature, and mingw lags the SDK for newer ETW/WFP surface; (d) `[*c]` pointer types everywhere lose optionality/sentinel information zigwin32 preserves.

### F8. Cost of hand-rolling the full surface

The minimal two-call example below took 2 externs + 4 structs + 8 constants ≈ 60 lines and worked on the first run (after fixing 0.16 std churn unrelated to Win32). Extrapolating over zPulsar's real surface:

- ETW consumption alone pulls a deep transitive struct closure: `EVENT_TRACE_LOGFILEW` → `EVENT_TRACE` → `EVENT_TRACE_HEADER`, `TRACE_LOGFILE_HEADER` → `TIME_ZONE_INFORMATION` → `SYSTEMTIME`, plus `EVENT_RECORD` → `EVENT_HEADER`/`EVENT_DESCRIPTOR`/`ETW_BUFFER_CONTEXT`/extended-data items, plus `TRACE_EVENT_INFO`/`EVENT_PROPERTY_INFO` for TDH — ~16 structs, several union-bearing.
- WFP net-events are worse: `FWPM_NET_EVENT2/3` is a tagged union over ~10 per-event structs, plus `FWP_BYTE_BLOB`, SIDs, and the giant `FWP_CONDITION_VALUE0` union — ~20+ structs where a single wrong union arm size shifts every later field.
- D3D11/DXGI is the killer: COM vtables must be transcribed in exact slot order (`ID3D11DeviceContext` alone has ~110 methods). A miscount compiles fine and calls the wrong method at runtime.
- Realistic total: ~60–70 functions, ~60–80 structs, dozens of enums/constants, 300+ COM vtable slots → **on the order of 500+ hand-maintained declarations**, each a potential silent ABI bug, duplicating what zigwin32 generates from Microsoft's own metadata.

Hand-rolled externs remain the right tool for a *narrow* escape hatch (one wrong/missing declaration) — the working example proves the technique is cheap at small scale. Layout pitfalls to respect when doing so: use `extern struct` (never `packed`) for C structs, `callconv(.winapi)` (never `.c`) for portability to x86, and comptime asserts for sizes/offsets (`MIB_TCPROW_OWNER_MODULE` = 160 bytes, `liCreateTimestamp` at offset 24 — no hidden padding on x64, but e.g. `EVENT_TRACE_PROPERTIES` = 120 bytes relies on `HANDLE` alignment).

### F9. Linking: no Windows SDK needed

Zig ships mingw-w64 `.def` exports for every DLL zPulsar needs — `advapi32.def.in` (contains `StartTraceW`), `iphlpapi.def` (`GetExtendedTcpTable`, `GetOwnerModuleFromTcpEntry`), `tdh.def`, `fwpuclnt.def`, `ws2_32.def.in`, `shell32.def`, `d3d11.def`, `dxgi.def` (verified in `lib/libc/mingw/lib-common/` of the 0.16.0 install). Plain `-ladvapi32 -liphlpapi ...` (or `linkSystemLibrary`) builds the import libs on the fly; the portable-exe goal is unaffected by the binding choice.

## Working examples (both compiled AND executed on Zig 0.16.0, x86_64-windows)

### Recommended approach: zigwin32

`build.zig.zon` dependency, created by `zig fetch --save=zigwin32 "git+https://github.com/marlersoft/zigwin32#main"`:

```zig
.dependencies = .{
    .zigwin32 = .{
        .url = "git+https://github.com/marlersoft/zigwin32?ref=main#9f15c276b4e9d05afd34a10d8662a7dfc34647ea",
        .hash = "win32-42.0.39-preview-mX5pFS564gPTezZn4v3TMxRnfJUrZNx1B_F2p2HKXOeG",
    },
},
```

`build.zig` (module import; no link flags needed — the extern `"dll"` names resolve via Zig's bundled import libs):

```zig
const win32 = b.dependency("zigwin32", .{});
// ...
.imports = &.{.{ .name = "win32", .module = win32.module("win32") }},
```

`main.zig`:

```zig
//! zigwin32 test: StartTraceW (ETW) + GetExtendedTcpTable (IP Helper).
//! zigwin32 main @ 9f15c27 (win32-42.0.39-preview), Zig 0.16.0.
const std = @import("std");
const win32 = @import("win32").everything;

pub fn main() !void {
    const gpa = std.heap.page_allocator;

    // --- GetExtendedTcpTable: size probe, then fill ---
    var size: u32 = 0;
    var rc = win32.GetExtendedTcpTable(null, &size, 0, 2, win32.TCP_TABLE_OWNER_MODULE_ALL, 0);
    std.debug.print("GetExtendedTcpTable(size probe) rc={d} size={d}\n", .{ rc, size });
    if (rc != 122) return error.UnexpectedRc; // ERROR_INSUFFICIENT_BUFFER

    const buf = try gpa.alignedAlloc(u8, .of(win32.MIB_TCPTABLE_OWNER_MODULE), size);
    defer gpa.free(buf);
    rc = win32.GetExtendedTcpTable(buf.ptr, &size, 1, 2, win32.TCP_TABLE_OWNER_MODULE_ALL, 0);
    if (rc != 0) return error.TcpTableFailed;
    const table: *const win32.MIB_TCPTABLE_OWNER_MODULE = @ptrCast(@alignCast(buf.ptr));
    std.debug.print("GetExtendedTcpTable OK: {d} rows\n", .{table.dwNumEntries});

    // --- StartTraceW: real-time session (needs admin; non-admin returns 5/ACCESS_DENIED,
    //     which still proves the call marshals correctly) ---
    const name = std.unicode.utf8ToUtf16LeStringLiteral("zPulsarInteropProbe2");
    const props_len = @sizeOf(win32.EVENT_TRACE_PROPERTIES) + (name.len + 1) * 2;
    const raw = try gpa.alignedAlloc(u8, .of(win32.EVENT_TRACE_PROPERTIES), props_len);
    defer gpa.free(raw);
    @memset(raw, 0);
    const props: *win32.EVENT_TRACE_PROPERTIES = @ptrCast(@alignCast(raw.ptr));
    props.Wnode.BufferSize = @intCast(props_len);
    props.Wnode.Flags = win32.WNODE_FLAG_TRACED_GUID;
    props.Wnode.ClientContext = 1; // QPC clock
    props.LogFileMode = win32.EVENT_TRACE_REAL_TIME_MODE;
    props.LoggerNameOffset = @sizeOf(win32.EVENT_TRACE_PROPERTIES);

    var handle: win32.CONTROLTRACE_HANDLE = 0;
    const src = win32.StartTraceW(&handle, name, props);
    std.debug.print("StartTraceW rc={d} handle={x}\n", .{ @intFromEnum(src), handle });
    if (src == .NO_ERROR) {
        _ = win32.ControlTraceW(handle, null, props, win32.EVENT_TRACE_CONTROL_STOP);
        std.debug.print("(session stopped)\n", .{});
    }
    std.debug.print("zigwin32 interop test PASSED\n", .{});
}
```

### Escape-hatch approach: hand-rolled externs (also verified)

Compiled with `zig build-exe main.zig -ladvapi32 -liphlpapi`; structs transcribed from SDK 10.0.26100.0 headers with comptime layout asserts:

```zig
//! Hand-rolled extern test: StartTraceW (advapi32) + GetExtendedTcpTable (iphlpapi).
const std = @import("std");
const win = std.os.windows;

const GUID = win.GUID;
const ULONG = u32;
const TRACEHANDLE = u64; // evntrace.h:307: typedef ULONG64 CONTROLTRACE_ID;

// wmistr.h: WNODE_HEADER (48 bytes on x64)
const WNODE_HEADER = extern struct {
    BufferSize: ULONG,
    ProviderId: ULONG,
    u1: extern union {
        HistoricalContext: u64,
        s: extern struct { Version: ULONG, Linkage: ULONG },
    },
    u2: extern union {
        CountLost: ULONG,
        KernelHandle: ?win.HANDLE,
        TimeStamp: i64, // LARGE_INTEGER
    },
    Guid: GUID,
    ClientContext: ULONG,
    Flags: ULONG,
};

// evntrace.h:1238: EVENT_TRACE_PROPERTIES
const EVENT_TRACE_PROPERTIES = extern struct {
    Wnode: WNODE_HEADER,
    BufferSize: ULONG,
    MinimumBuffers: ULONG,
    MaximumBuffers: ULONG,
    MaximumFileSize: ULONG,
    LogFileMode: ULONG,
    FlushTimer: ULONG,
    EnableFlags: ULONG,
    u: extern union { AgeLimit: i32, FlushThreshold: i32 },
    NumberOfBuffers: ULONG,
    FreeBuffers: ULONG,
    EventsLost: ULONG,
    BuffersWritten: ULONG,
    LogBuffersLost: ULONG,
    RealTimeBuffersLost: ULONG,
    LoggerThreadId: ?win.HANDLE,
    LogFileNameOffset: ULONG,
    LoggerNameOffset: ULONG,
};

const WNODE_FLAG_TRACED_GUID: ULONG = 0x00020000;
const EVENT_TRACE_REAL_TIME_MODE: ULONG = 0x00000100;

extern "advapi32" fn StartTraceW(
    TraceId: *TRACEHANDLE,
    InstanceName: win.LPCWSTR,
    Properties: *EVENT_TRACE_PROPERTIES,
) callconv(.winapi) ULONG;

// tcpmib.h:143
const TCPIP_OWNING_MODULE_SIZE = 16;
const MIB_TCPROW_OWNER_MODULE = extern struct {
    dwState: u32,
    dwLocalAddr: u32,
    dwLocalPort: u32,
    dwRemoteAddr: u32,
    dwRemotePort: u32,
    dwOwningPid: u32,
    liCreateTimestamp: i64, // LARGE_INTEGER
    OwningModuleInfo: [TCPIP_OWNING_MODULE_SIZE]u64,
};
const MIB_TCPTABLE_OWNER_MODULE = extern struct {
    dwNumEntries: u32,
    table: [1]MIB_TCPROW_OWNER_MODULE, // variable-length in reality
};

const TCP_TABLE_OWNER_MODULE_ALL: u32 = 8; // iprtrmib.h TCP_TABLE_CLASS
const AF_INET: ULONG = 2;

extern "iphlpapi" fn GetExtendedTcpTable(
    pTcpTable: ?*anyopaque,
    pdwSize: *u32,
    bOrder: i32, // BOOL (std.os.windows.BOOL is a typed enum in 0.16 — avoid for raw externs)
    ulAf: ULONG,
    TableClass: u32,
    Reserved: ULONG,
) callconv(.winapi) ULONG;

const ERROR_SUCCESS: ULONG = 0;
const ERROR_ACCESS_DENIED: ULONG = 5;
const ERROR_INSUFFICIENT_BUFFER: ULONG = 122;
const ERROR_ALREADY_EXISTS: ULONG = 183;

pub fn main() !void {
    comptime {
        // Layout ground truth from SDK 10.0.26100.0 (x64):
        std.debug.assert(@sizeOf(WNODE_HEADER) == 48);
        std.debug.assert(@sizeOf(EVENT_TRACE_PROPERTIES) == 120);
        std.debug.assert(@sizeOf(MIB_TCPROW_OWNER_MODULE) == 160);
        std.debug.assert(@offsetOf(MIB_TCPROW_OWNER_MODULE, "liCreateTimestamp") == 24);
        std.debug.assert(@offsetOf(MIB_TCPROW_OWNER_MODULE, "OwningModuleInfo") == 32);
    }

    // --- GetExtendedTcpTable: two-call size-then-fill pattern ---
    var size: u32 = 0;
    var rc = GetExtendedTcpTable(null, &size, 0, AF_INET, TCP_TABLE_OWNER_MODULE_ALL, 0);
    std.debug.print("GetExtendedTcpTable(size probe) rc={d} size={d}\n", .{ rc, size });
    if (rc != ERROR_INSUFFICIENT_BUFFER) return error.UnexpectedRc;

    const gpa = std.heap.page_allocator;
    const buf = try gpa.alignedAlloc(u8, .of(MIB_TCPTABLE_OWNER_MODULE), size);
    defer gpa.free(buf);
    rc = GetExtendedTcpTable(buf.ptr, &size, 1, AF_INET, TCP_TABLE_OWNER_MODULE_ALL, 0);
    if (rc != ERROR_SUCCESS) return error.TcpTableFailed;
    const table: *const MIB_TCPTABLE_OWNER_MODULE = @ptrCast(buf.ptr);
    const rows = @as([*]const MIB_TCPROW_OWNER_MODULE, &table.table)[0..table.dwNumEntries];
    std.debug.print("GetExtendedTcpTable OK: {d} rows\n", .{rows.len});
    var shown: usize = 0;
    for (rows) |r| {
        if (shown == 3) break;
        const port = std.mem.bigToNative(u16, @truncate(r.dwLocalPort));
        std.debug.print("  pid={d} state={d} local_port={d}\n", .{ r.dwOwningPid, r.dwState, port });
        shown += 1;
    }

    // --- StartTraceW ---
    const name = std.unicode.utf8ToUtf16LeStringLiteral("zPulsarInteropProbe");
    const props_len = @sizeOf(EVENT_TRACE_PROPERTIES) + (name.len + 1) * 2;
    const raw = try gpa.alignedAlloc(u8, .of(EVENT_TRACE_PROPERTIES), props_len);
    defer gpa.free(raw);
    @memset(raw, 0);
    const props: *EVENT_TRACE_PROPERTIES = @ptrCast(raw.ptr);
    props.Wnode.BufferSize = @intCast(props_len);
    props.Wnode.Flags = WNODE_FLAG_TRACED_GUID;
    props.Wnode.ClientContext = 1; // QPC
    props.LogFileMode = EVENT_TRACE_REAL_TIME_MODE;
    props.LoggerNameOffset = @sizeOf(EVENT_TRACE_PROPERTIES);

    var handle: TRACEHANDLE = 0;
    rc = StartTraceW(&handle, name, props);
    std.debug.print("StartTraceW rc={d} handle={x}\n", .{ rc, handle });
    switch (rc) {
        ERROR_SUCCESS, ERROR_ACCESS_DENIED, ERROR_ALREADY_EXISTS => {},
        else => return error.UnexpectedStartTraceRc,
    }
    std.debug.print("hand-rolled interop test PASSED\n", .{});
}
```
